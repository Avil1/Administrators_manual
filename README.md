# Руководство Администратора

## Аннотация

Настоящий документ является руководством администратора информационной системы и содержит полное описание процедур установки, настройки, эксплуатации и технического обслуживания системы. Документ предназначен для системных администраторов и инженеров технической поддержки, осуществляющих развертывание и сопровождение системы в промышленной среде.

---

## Термины и определения

*Таблица 1 — Термины и определения*

| Термин | Определение |
|--------|-------------|
| Администратор | Пользователь системы, обладающий правами на выполнение операций управления, настройки и обслуживания |
| Аппаратное обеспечение (АО) | Совокупность физических устройств, обеспечивающих функционирование системы |
| Программное обеспечение (ПО) | Совокупность программных компонентов, реализующих функциональность системы |
| Резервная копия | Копия данных системы, созданная для возможности восстановления в случае утраты или повреждения оригинальных данных |
| Развертывание | Процесс установки и первоначальной конфигурации системы на целевом оборудовании |
| Роль | Набор прав и привилегий, определяющий возможности пользователя в системе |
| Техобслуживание | Комплекс мероприятий, направленных на поддержание системы в работоспособном состоянии |
| RTO | Recovery Time Objective — целевое время восстановления системы после сбоя |
| RPO | Recovery Point Objective — целевая точка восстановления, определяющая максимально допустимый объем потери данных |
## Введение

Настоящее руководство администратора разработано в соответствии с требованиями ГОСТ 2.105-95 «Единая система конструкторской документации. Общие требования к текстовым документам» и ГОСТ 19.505-79 «Руководство администратора. Требования к содержанию и оформлению».

Документ описывает полный жизненный цикл администрирования системы: от требований к аппаратному обеспечению и процедур развертывания до регламентов технического обслуживания и аварийного восстановления.

Руководство структурировано таким образом, чтобы администратор мог последовательно выполнить все необходимые операции по вводу системы в эксплуатацию и ее дальнейшему сопровождению. Каждый раздел содержит конкретные инструкции, команды и параметры конфигурации.

Документ предназначен для использования специалистами, обладающими базовыми знаниями в области администрирования серверных систем, работы с операционными системами семейства Linux/Windows и сетевыми технологиями.

## Глава 1. Назначение

### 1.1. Общие сведения

Информационная система предназначена для автоматизации бизнес-процессов организации, включая управление данными, обработку запросов пользователей, формирование отчетности и интеграцию с внешними системами.

### 1.2. Функциональные возможности

Система обеспечивает выполнение следующих функций:

- Управление пользователями и разграничение прав доступа на основе ролевой модели
- Хранение и обработка структурированных данных
- Формирование отчетов и аналитических материалов
- Интеграция с внешними информационными системами через API
- Ведение журналов событий и аудита действий пользователей
- Резервное копирование и восстановление данных

### 1.3. Область применения

Система применяется в корпоративной среде для обеспечения информационных процессов организации. Система может быть развернута как в локальной инфраструктуре заказчика, так и в облачной среде.

### 1.4. Состав системы

Система включает следующие компоненты:

- Сервер приложений
- Сервер баз данных
- Веб-интерфейс
- Службы фоновой обработки задач
- Служба мониторинга и логирования

### 3.1. Физическое подключение

1. Установить серверы в стойку согласно схеме размещения
2. Подключить серверы к источникам бесперебойного питания (ИБП)

4. Подключить консольный кабель для первоначальной настройки (при необходимости)

### 3.2. Сетевая конфигурация

Настроить сетевые интерфейсы серверов:

**Для Linux:**
```bash
# Редактирование сетевого интерфейса
sudo nano /etc/netplan/01-netcfg.yaml

# Пример конфигурации
network:
  version: 2
  ethernets:
    eth0:
      addresses:
        - 192.168.1.10/24
      gateway4: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]

# Применение конфигурации
sudo netplan apply
```

**Для Windows Server:**
```powershell
# Настройка статического IP-адреса
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.1.10 -PrefixLength 24 -DefaultGateway 192.168.1.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 8.8.8.8, 8.8.4.4
```

## Глава 4. Разворачивание системы

### 4.1. Подготовка среды

#### 4.1.1. Установка зависимостей

**Для Ubuntu/Debian:**
```bash
sudo apt update
sudo apt upgrade -y
sudo apt install -y postgresql postgresql-contrib nginx python3 python3-pip redis-server
```

**Для CentOS/RHEL:**
```bash
sudo yum update -y
sudo yum install -y postgresql-server postgresql-contrib nginx python3 python3-pip redis
```

#### 4.1.2. Настройка firewall

```bash
# Ubuntu (UFW)
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 8080/tcp
sudo ufw enable

# CentOS (firewalld)
sudo firewall-cmd --permanent --add-port=22/tcp
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --permanent --add-port=443/tcp
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

### 4.2. Установка системы

```bash
# Клонирование репозитория
git clone https://github.com/organization/system.git /opt/system
cd /opt/system

# Создание виртуального окружения
python3 -m venv venv
source venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt

# Настройка конфигурации
cp config.example.py config.py
nano config.py
```

### 4.3. Инициализация базы данных

```bash
# Создание базы данных
sudo -u postgres psql
CREATE DATABASE system_db;
CREATE USER system_user WITH PASSWORD 'secure_password';
GRANT ALL PRIVILEGES ON DATABASE system_db TO system_user;
\q

# Применение миграций
python manage.py migrate
python manage.py loaddata initial_data.json
```

### 4.4. Настройка веб-сервера

```bash
# Конфигурация Nginx
sudo nano /etc/nginx/sites-available/system

server {
    listen 80;
    server_name system.example.com;
    
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

sudo ln -s /etc/nginx/sites-available/system /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

### 4.5. Запуск системы

```bash
# Запуск через systemd
sudo nano /etc/systemd/system/system.service

[Unit]
Description=System Application
After=network.target postgresql.service

[Service]
User=system_user
Group=system_user
WorkingDirectory=/opt/system
ExecStart=/opt/system/venv/bin/python manage.py runserver 0.0.0.0:8080
Restart=always

[Install]
WantedBy=multi-user.target

sudo systemctl daemon-reload
sudo systemctl enable system
sudo systemctl start system
```

### 4.6. Проверка развертывания


### 6.2. Создание новой роли

```bash

# 1. Войти в систему под учетной записью администратора
# 2. Перейти в раздел "Управление" -> "Роли"
# 3. Нажать "Создать роль"

```

```python
from django.contrib.auth.models import Group, Permission
from django.contrib.contenttypes.models import ContentType

# Создание группы (роли)

# Добавление прав
```

## Глава 8. Резервное копирование

### 8.1. Стратегия резервного копирования

Система использует комбинированную стратегию резервного копирования:

- **Полное резервное копирование** — еженедельно (воскресенье, 02:00)
- **Инкрементальное резервное копирование** — ежедневно (02:00)
- **Резервное копирование базы данных** — каждые 6 часов

### 8.2. Процедура резервного копирования

#### 8.2.1. Резервное копирование базы данных

```bash
#!/bin/bash
# Скрипт резервного копирования БД

BACKUP_DIR="/backup/database"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="system_db"
DB_USER="system_user"

# Создание резервной копии
pg_dump -U $DB_USER -d $DB_NAME -F c -f $BACKUP_DIR/db_backup_$DATE.dump

# Сжатие
gzip $BACKUP_DIR/db_backup_$DATE.dump

# Удаление старых бэкапов (старше 30 дней)
find $BACKUP_DIR -type f -mtime +30 -delete

# Логирование
echo "$(date): Резервная копия БД создана" >> /var/log/system/backup.log
```

#### 8.2.2. Резервное копирование файлов

```bash
#!/bin/bash
# Скрипт резервного копирования файлов

BACKUP_DIR="/backup/files"
SOURCE_DIR="/opt/system"
DATE=$(date +%Y%m%d_%H%M%S)

# Создание архива
tar -czf $BACKUP_DIR/files_backup_$DATE.tar.gz $SOURCE_DIR

# Удаление старых бэкапов (старше 90 дней)
find $BACKUP_DIR -type f -mtime +90 -delete

echo "$(date): Резервная копия файлов создана" >> /var/log/system/backup.log
```

### 8.3. Расписание резервного копирования

*Таблица 6 — Расписание резервного копирования*

| Тип бэкапа | Частота | Время выполнения | Хранение | Размер |
|------------|---------|-----------------|----------|--------|
| Полный бэкап БД | Еженедельно | Вс 02:00 | 90 дней | ~5 ГБ |
| Инкрементальный бэкап БД | Ежедневно | 02:00 | 30 дней | ~500 МБ |
| Бэкап файлов | Еженедельно | Вс 03:00 | 180 дней | ~10 ГБ |
| Конфигурация | Ежедневно | 04:00 | 365 дней | ~10 МБ |

### 8.4. Настройка автоматического выполнения

```bash
# Добавление задач в cron
sudo crontab -e

# Резервное копирование БД каждые 6 часов
0 */6 * * * /opt/system/scripts/backup_db.sh

# Полное резервное копирование по воскресеньям
0 2 * * 0 /opt/system/scripts/full_backup.sh

# Инкрементальное копирование ежедневно
0 2 * * 1-6 /opt/system/scripts/incremental_backup.sh
```

### 8.5. Проверка целостности резервных копий

```bash
# Проверка архива
tar -tzf /backup/files/files_backup_20260912.tar.gz > /dev/null && echo "Архив цел" || echo "Архив поврежден"

# Проверка бэкапа БД
pg_restore --list /backup/database/db_backup_20260912.dump > /dev/null && echo "Бэкап БД цел" || echo "Бэкап БД поврежден"
```
## Глава 9. Аварийное восстановление

### 9.1. Классификация инцидентов

*Таблица 7 — Классификация инцидентов*

| Уровень | Описание | Время реакции | Время восстановления |
|---------|----------|--------------|---------------------|
| Критический | Полная недоступность системы | 15 минут | 4 часа |
| Высокий | Частичная недоступность функций | 30 минут | 8 часов |
| Средний | Снижение производительности | 2 часа | 24 часа |
| Низкий | Незначительные проблемы | 8 часов | 72 часа |

### 9.2. Процедура восстановления после сбоя

#### 9.2.1. Восстановление базы данных

```bash
# Остановка приложения
sudo systemctl stop system

# Восстановление из резервной копии
pg_restore -U system_user -d system_db -c /backup/database/db_backup_20260912.dump.gz

# Запуск приложения
sudo systemctl start system

# Проверка работоспособности
curl -I http://localhost:8080
```

#### 9.2.2. Восстановление из полной резервной копии

```bash
# Остановка всех служб
sudo systemctl stop system
sudo systemctl stop nginx

# Восстановление файлов
tar -xzf /backup/files/files_backup_20260912.tar.gz -C /

# Восстановление БД
pg_restore -U system_user -d system_db -c /backup/database/db_backup_20260912.dump.gz

# Запуск служб
sudo systemctl start nginx
sudo systemctl start system

# Проверка
sudo systemctl status system
```

### 9.3. Целевые показатели восстановления

- **RTO (Recovery Time Objective):** 4 часа для критических инцидентов
- **RPO (Recovery Point Objective):** 6 часов (максимальная потеря данных)

### 9.4. План действий при аварийных ситуациях

#### 9.4.1. Отказ сервера приложений

1. Определить причину отказа (аппаратная/программная)
2. При аппаратном отказе — переключиться на резервный сервер
3. При программном отказе — перезапустить службу
4. Если перезапуск не помог — восстановить из резервной копии
5. Задокументировать инцидент

#### 9.4.2. Отказ сервера баз данных

1. Проверить статус службы PostgreSQL
2. Попытаться перезапустить службу
3. Если не помогло — восстановить из последней резервной копии
4. Проверить целостность данных
5. Уведомить пользователей о возможной потере данных

#### 9.4.3. Потеря данных

1. Определить объем и характер потерянных данных
2. Найти последнюю актуальную резервную копию
3. Выполнить восстановление данных
4. Проверить целостность восстановленных данных
5. Составить отчет об инциденте

### 9.5. Тестирование процедуры восстановления

Регулярное тестирование процедуры восстановления проводится согласно графику:

- **Полное тестирование:** раз в квартал
- **Частичное тестирование:** раз в месяц
- **Проверка резервных копий:** еженедельно

```bash
# Скрипт тестового восстановления
#!/bin/bash
TEST_DIR="/tmp/restore_test"
mkdir -p $TEST_DIR

# Тестовое восстановление БД
pg_restore -l /backup/database/db_backup_latest.dump > $TEST_DIR/restore_test.log
if [ $? -eq 0 ]; then
    echo "Тестовое восстановление БД успешно"
else
    echo "Ошибка при тестовом восстановлении БД"
fi

# Очистка
rm -rf $TEST_DIR
```
